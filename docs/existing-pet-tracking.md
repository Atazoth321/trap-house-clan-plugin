# Existing pet recognition

The client recognizes all 55 currently configured automatic pet reward families in inventory or a loaded bank, including explicitly supported recolours and transformed forms. It reads containers on inventory/bank changes and during the existing periodic progress check. Open the bank once to load its contents; the plugin does not open interfaces, withdraw items or perform game actions. Pick up a following pet for inventory recognition. Pets visible only in a POH menagerie, following NPCs, collection-log history and reclaim interfaces are not read by this change.

Each pet uses exactly the existing `COLLECTION` key used by a fresh collection-log unlock. The backend's unique collection history pays at most once per member and pet family, and the Pets reward browser shows its existing received status and points. Recolouring, banking, relogging or receiving another copy cannot repay an already credited automatic pet unlock. Pets obtained before plugin installation qualify when observed. Amounts remain the backend's configured values; no goals, migrations or separate historical-pet awards are created.

The client submits each observed family once per tracking session and retries on later container scans if the submission queue is full. Resetting ranking credentials/endpoint or changing character clears that local observation cache; server award history remains authoritative. Bank placeholders and zero-quantity entries do not qualify. An explicit item-ID allowlist prevents ordinary cats, pet rocks, quest foxes, equipment or similarly named items from qualifying. Pet reward artwork uses the canonical in-game item sprite.

Historical staff-approved generic pet claims do not identify an individual pet in structured data, so they cannot automatically reconcile with named automatic pet unlocks. Staff should check for a prior manual payment before enabling historical recognition for such cases. The existing client-trust model is unchanged.

Validation covers inventory and bank reads, unavailable bank data, transformed-family normalization, placeholders/unrelated items, duplicate scans, session/character resets, queue retry, all 55 server/client reward-key matches and game-sprite selection. Existing backend integration tests cover once-only automatic collection awards and member-specific received status. Live inventory/bank behavior still requires an in-game check after release.
